## 1. Inventory Overview & Classification Schema

This master feature inventory establishes the definitive, exhaustive accounting of every planned, specified, and implemented capability within the ResearchLens platform. The inventory covers all foundational modules defined in the Department of Information Technology project specifications (`IMPLEMENTATION_STATUS.md`, BIP Project ID `2026AC272`), historical review presentations (`NLP FIRST REVIEW.pptx`), and evolutionary engineering tasks (Tasks 1A–19, N1–N2, and AI Activation).

### Status Taxonomy

Every feature in this inventory is assigned one of the seven mandatory status codes:

- **`IMPLEMENTED_AND_VERIFIED`**: The capability is fully implemented in the active codebase, exhibits complete unit/integration test coverage, and has been verified against live runtime environments (API probes, database state, FAISS index, and/or UI Playwright sessions).
- **`IMPLEMENTED_PARTIALLY_VERIFIED`**: The capability is implemented in source code and verified under mock or isolated conditions, but full live end-to-end execution is constrained (e.g., live cloud LLM fallback is blocked by local data-privacy guard).
- **`PARTIALLY_IMPLEMENTED`**: Core scaffolding or baseline heuristics exist, but higher-order functionality (e.g., interactive tour guides or advanced analytics) remains incomplete.
- **`MISSING`**: The capability was explicitly specified in project roadmaps but has no functional implementation in the current codebase.
- **`BROKEN_OR_BLOCKED`**: The capability is implemented but currently non-functional due to an active bug, or cannot function in its current state (e.g., production launch blocked by placeholder secret keys).
- **`PLANNED_ONLY`**: The capability is documented for upcoming project phases (e.g., Firebase Authentication, public TLS reverse proxy) and has not yet been introduced into the active working tree.
- **`UNVERIFIED`**: Source code exists, but automated tests and runtime diagnostics could not substantiate its behavioral correctness.
